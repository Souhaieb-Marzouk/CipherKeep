# CipherKeep 2.2.1

CipherKeep 2.2.1 is a security-maintenance release. Import behaviour, the
Android interface and the Firefox extension are unchanged from 2.2.0.

## What changed

- The Rust core no longer links the third-party `pgp` crate. That crate pulled
  the `rsa` and `crypto-bigint` versions covered by `RUSTSEC-2023-0071` and the
  constant-time advisory in `crypto-bigint` 0.5, and neither upstream has a
  fixed release on the branches the crate uses.
- Proton PGP imports now use a small in-tree OpenPGP reader that implements only
  what a Proton `data.pgp` export needs: passphrase-derived session keys
  (`SKESK` v4 with simple, salted and iterated/salted string-to-key), integrity-
  protected encrypted data (`SEIPD` v1 with the SHA-1 modification detection
  code), ZIP/ZLIB decompression and literal data.
- No asymmetric OpenPGP code — no RSA, DSA, ECDSA or EdDSA parsing — is linked
  into either client any more, so an import never touches a public key.
- The new reader rejects every packet layout outside that subset, verifies the
  modification detection code before returning any plaintext, and caps packet
  count, packet size, decompressed size, nesting depth and the number of
  password candidates.

## Verification

The import path is covered by fixtures produced by GnuPG 2.4.9 and OpenPGP.js 6:

- AES-128 and AES-256, armored and binary, compressed and uncompressed
- simple, salted and iterated/salted string-to-key, including SHA-1 and SHA-512
- session keys supplied directly by the string-to-key specifier and wrapped in
  the packet
- wrong passphrase, tampered ciphertext and truncated armor all fail with the
  same redacted error

## Dependency and CI

- `cargo deny --all-features check` passes again: advisories, bans, licences and
  sources are all clean.
- The Rust workspace test suite, `cargo fmt` and `cargo clippy -D warnings` pass.
