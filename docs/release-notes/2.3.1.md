# CipherKeep 2.3.1

CipherKeep 2.3.1 hardens the new manual sync, makes failures explain themselves
and fixes autofill for native apps and locked vaults.

## Sync robustness

- A single unreadable record in a manifest no longer aborts the whole sync: it is
  skipped and the remaining records are applied.
- Fixed the repair path: after re-sealing legacy records it persisted the old,
  failing manifest instead of the repaired merge, which is why a download could
  fail on every retry.
- If the merge rejects a manifest, records that are not valid v2 envelopes are
  dropped and the merge is retried once.
- Legacy records are not re-sealed while they are tombstones, so deletions are
  preserved through the repair path.
- The relay read timeout is raised from 30 s to 120 s (connect 20 s) so a large
  manifest is not aborted on a slow mobile connection.
- Upload and download failures now show the underlying reason (for example
  `Download failed: relay GET failed: 500.`) instead of one generic line, and the
  exception is written to logcat under `CipherKeepSync`.

## Why the phone could close after a large download

The vault list built a native search index for every item during composition.
With roughly 700 imported records that meant hundreds of JNI calls on the UI
thread right after the download. Search is now an in-memory filter, so opening a
large vault after a download no longer does that work on the UI thread.

## Autofill

- Web pages still match by exact origin (with `www.` treated as equivalent, and
  URLs stored without a scheme are understood).
- Native apps no longer require a web domain: items are matched against the
  package name and the application label, scored by title, URL, username and
  notes, and the best five are offered. This covers banking, social and shopping
  apps that expose no origin.
- If the vault is locked or the app process was restarted, the autofill popup now
  shows an **Unlock CipherKeep to autofill** suggestion instead of staying empty.
  Tapping it opens CipherKeep; after unlocking, tap the field again and the
  matching records appear.
- Autofill never fills without an explicit tap and still never submits a form.

## Compatibility

- Android only; no vault, record or relay protocol change. The signed Firefox
  2.2.4 package remains interoperable.
