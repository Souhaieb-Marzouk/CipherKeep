# CipherKeep 2.3.5

CipherKeep 2.3.5 fixes autofill matching for apps and websites whose login lives
on a different subdomain, and adds support for split one-time-code boxes.

## Matching at registrable-domain level

Logins are no longer matched only on an exact host. `sso.crunchyroll.com` now
matches a saved `crunchyroll.com` login, and `chat.z.ai` matches `z.ai`, while a
different site still never matches. Multi-part public suffixes (`co.uk`,
`com.au`, …) are handled so `evil.co.uk` cannot match `co.uk`.

Verified on the OPPO CPH2173 (Android 14) with the vault unlocked:

- Crunchyroll: two saved logins matched, both suggestion cards shown and
  readable; the login form was filled.
- DuckDuckGo to `https://chat.z.ai/auth`: the page domain was detected, four
  saved logins matched and were listed.
- TryHackMe: the email/password form matched one saved login and was filled.
- Locked vault: the "Unlock CipherKeep" card appears and tapping it opens the
  app.

## Split one-time-code boxes

Some apps show six separate one-character numeric fields instead of one code
field. When four or more such fields are found, the current code is split across
them digit by digit. A single code field continues to receive the whole code.
The detection now also recognises `smsotp` hints and numeric fields whose id or
hint contains `code`, `pin`, `token`, `otp` or `verification`.

## Known limitation: TryHackMe two-factor screen

The six code boxes on TryHackMe's two-factor screen never start an Android
autofill session: after tapping them, logcat shows no `AutofillSession` and
`dumpsys autofill` records no new request for the activity. Because the app does
not publish those fields to autofill, no autofill service can fill them,
CipherKeep included. Copy the code from the vault entry instead. An optional
accessibility-based helper could fill such fields in a future release, but it
requires a separate, explicit permission.

## Diagnostics

Autofill now logs field metadata (hints, input type, maximum length, detection
result) under `CipherKeepAutofill` and `CipherKeepAutofillFields`; no entered
value or secret is ever logged.

## Compatibility

- Android only; no vault, record or relay protocol change. The signed Firefox
  2.2.4 package remains interoperable.
