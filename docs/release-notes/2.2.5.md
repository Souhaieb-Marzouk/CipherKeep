# CipherKeep 2.2.5

CipherKeep 2.2.5 repairs sync against vaults that still have records from older
builds, makes conflict choices stick, and adds import progress.

## Sync repair

- When a merge produces records that cannot be opened, the app now re-seals the
  remote records under the derived item key once and merges again. Records
  written before 2.2.4 carry a random item key, so mixing them with local records
  made every field unreadable, aborted the whole sync and left the relay serving
  the same unreadable manifest forever — which is why a new relay token did not
  help.
- The repair keeps each remote record's original actor and creation time, so it
  does not reorder events, and it overwrites the relay with readable records on
  the same run.
- Each installation regenerates its sync actor when a vault is created or joined,
  so a cloned app profile cannot share a device identity.

## Conflict resolution

- **Keep left** and **Keep right** now rebuild the item with the chosen field and
  a clock above both sides, save the canonical record and push it on the next
  sync. Previously the choice was sent through a path that rejected records whose
  wrapped keys differed, failed silently, and was reported again on every sync.
- Resolution no longer depends on the raw wrapped key matching, and the resolved
  record is stored with the item.

## Import progress

- **Import passwords** now shows a determinate progress bar with live counts:
  records processed, imported, failed and (when finished) skipped.
- Every parsed record is counted even when its save fails, so a partial import is
  reported instead of aborting at the first error.
- The same progress contract is used for Bitwarden JSON, KeePass `.kdbx`,
  Proton PGP/ZIP and plain CSV/JSON imports, with a stage label while the file is
  read and decrypted.

## Compatibility

- The Firefox extension is unchanged from 2.2.4; the sync record format and
  relay protocol are unchanged, so Android 2.2.5 and Firefox 2.2.4 interoperate.
