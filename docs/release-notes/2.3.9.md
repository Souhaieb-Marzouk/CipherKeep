# CipherKeep 2.3.9

CipherKeep 2.3.9 adds the “save this login” prompt, completes family sharing,
fixes vault navigation and cleans up the Security and Advanced settings screens.

## Autofill save prompt

- When a login is typed by hand and the form is submitted, CipherKeep offers to
  store it through a notification (“Save this login to CipherKeep?”) with Save
  and Not now. The user stays in the app they just logged into.
- On Save, the record is created in the background with the app/website title,
  username, password and URL.
- The vault now defaults to “Recent” order, so every new record appears at the
  top of the list.
- Duplicate username/password pairs are not prompted again.
- If notification permission is denied, the login is stored silently when the
  vault is unlocked.

## Family sharing completed

- Owner identity creation, member identity creation (member id, public key,
  secret, fingerprint with copy buttons), vault id display, invitation, envelope
  display (ephemeral public, nonce, ciphertext) and member join are now a full
  flow.
- The join form now asks for the envelope's ephemeral public key; it previously
  used the member's own public key, which made joins fail.
- Role selection is available both for invitations and for joining, so viewer
  envelopes unwrap correctly.
- Revoke still rotates the vault key and rewraps remaining members.

## Navigation and folders

- The vault list, search, folder/tag filter, favourites toggle and sort order are
  now held above the detail screen. Pressing Back returns to the same scroll
  position and the same filtered list instead of the top of an unfiltered list.
- Each folder row has an Open action that filters the list to that folder.

## Security and Advanced settings

- The duplicate Password health card was removed from the Security tab.
- The Security tab now contains a plain-language “How CipherKeep protects you”
  card (local encryption, screenshots blocked, no cloud backup, no silent
  network, auto-lock).
- The security overview score now counts distinct at-risk items, so it stays a
  meaningful 0–100 value instead of collapsing to 0 when categories overlap.
- The Design token gallery button was removed from Appearance.
- The old Security block was removed from Advanced settings because it now lives
  in the Security tab.

## Hardware unlock

- When an authenticator returns the PRF value only on assertion, enrollment now
  performs that first assertion automatically instead of failing.

## Documentation

- `Full_Guide_Tests.html` contains the complete test procedures for emergency
  access, travel mode, family sharing, email aliases, hardware unlock and
  local-folder sync, including every field, expected result and troubleshooting
  step.

## Compatibility

- Android only; no vault, record or relay protocol change. The signed Firefox
  2.2.4 package remains interoperable.
