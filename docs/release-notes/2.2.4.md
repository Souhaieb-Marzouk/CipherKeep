# CipherKeep 2.2.4

CipherKeep 2.2.4 fixes cross-device sync after pairing and adds the missing
device-management controls.

## Sync fixes

- Item keys are now derived deterministically from the vault key and the item id
  instead of being random per save. A device that re-encrypts an item therefore
  writes fields the other device can still open, which removes the
  `Sync failed.` state and the wall of field conflicts that appeared after a
  phone joined a vault and then synced again.
- Unchanged items keep their stored canonical sync record, so a repeated sync
  re-sends the same record instead of re-sealing every field with a fresh nonce.
  That was the cause of phantom conflicts on every second sync.
- Each installation now has a random device actor id and uses the item's Lamport
  clock as the record counter, so concurrent edits resolve deterministically
  instead of colliding with an identical clock.
- Conflict resolution stores the resolved canonical record together with the
  item, so a resolved conflict stays resolved after the next sync.
- The Firefox extension now caches each item's canonical record and reuses it
  while the ciphertext is unchanged, so repeated browser syncs no longer report
  conflicts against the extension's own previous upload.

## Joining without a new password

- **Join a vault from another device** no longer asks for a new master password.
  The phone keeps the master password already used on that device; the password
  is held only while the vault is unlocked and is cleared on lock, travel mode
  and process close.
- Joining still replaces the local vault contents with the paired vault and pulls
  its items once.

## Pairing QR code

- **Generate pairing code** now renders the code as a QR image, and **Scan QR**
  under the join section reads it with the camera, so two phones can pair without
  copying text.
