# CipherKeep 2.2.7

CipherKeep 2.2.7 fixes biometric unlock failing after the app auto-locks and the
screen is locked, and repairs the CI toolchain pin.

## Biometric unlock

The previous implementation used an auth-per-use Keystore key and passed its
cipher to BiometricPrompt as a CryptoObject. Initialising such a cipher can throw
`UserNotAuthenticatedException` once the device has been locked; the app swallowed
that exception and handed an **uninitialised** cipher to the prompt. Authentication
then succeeded and `doFinal` failed, which surfaced as *"Biometric unlock failed.
Use your master password"*. Toggling biometrics only worked because it created a
fresh wrap.

- The Keystore key is now time-bound: it is unlocked by a successful biometric or
  device-credential authentication and stays usable for 60 seconds.
- The flow authenticates first and only then initialises the cipher and performs
  `doFinal`, so there is no uninitialised-cipher window and no dependence on
  CryptoObject behaviour that differs between OEMs and Android versions.
- The key moved to a new alias (`cipherkeep.biometric.v2`); the old auth-per-use
  key is deleted when the new one is created. The wrapped master secret is now
  version 2, so an old wrap is discarded instead of failing at unlock.
- A Keystore key invalidated by a biometric-enrolment change is detected and
  cleared with the message "Biometric data changed. Re-enable biometric unlock…"
  instead of a generic failure.

**After upgrading, enable biometric unlock once more** (Settings → Advanced
settings → Biometric unlock). The previous wrap cannot be migrated by design.

## CI toolchain

- The rust job pinned `dtolnay/rust-toolchain` to a non-existent commit and the
  action then tried to install a non-existent Rust 1.120.0. The action is now
  pinned to the head of the real `1.99.1` ref
  (`263313d2989f864a2b8613f97277288638e7d8f8`), matching the workflow's
  `toolchain: 1.99.1`.

## Compatibility

- Android only; no vault, sync or protocol change. The Firefox 2.2.4 signed
  package remains interoperable and is unchanged.
