# CipherKeep 2.3.2

CipherKeep 2.3.2 completes the autofill experience: one-time codes, a readable
suggestion card on every device, a list when several records match, and better
matching inside browsers.

## One-time codes

- A one-time-code field (OTP/TOTP/2FA, `oneTimeCode` hint, numeric “code” field)
  is now detected and filled with the current code computed from the saved
  `otpauth://` secret, alongside the username and password.
- Forms that only ask for a code are supported too.

## Suggestion card

- Suggestions now use CipherKeep's own layout with an explicit white background,
  dark title and grey subtitle, instead of the platform list item. This fixes the
  white-on-white suggestion seen on some devices and makes the record title
  readable everywhere.
- The subtitle shows the username, or the site host when there is no username.

## Several records for the same app

- One dataset is emitted per matching record (up to five), each with its own
  readable card, so the autofill strip lists all candidates and the user picks
  the right one. Previously the reused platform presentation and the multi-item
  list made the choice invisible on some devices.
- Ties are ordered by the match score computed from title, URL, username and
  notes.

## Browsers

- The web domain is now read from any node in the structure, not only the root,
  which covers browsers that attach the origin lower in the tree.
- If a known browser still provides no domain, the five most recently updated
  saved logins with a URL are offered so the user can choose one; nothing is
  filled without a tap.
- Exact-origin matching and the `www.` equivalence are unchanged, so a saved
  login is still not offered for a different site.

## Compatibility

- Android only; no vault, record or relay protocol change. The signed Firefox
  2.2.4 package remains interoperable.
