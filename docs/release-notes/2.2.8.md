# CipherKeep 2.2.8

CipherKeep 2.2.8 fixes a critical regression introduced in 2.2.7 that could stop
the app from opening its encrypted database after the master password was
accepted.

## What went wrong in 2.2.7

- The wrapped-secret format version was bumped globally to mark the new biometric
  wrap. That format is also used to wrap the SQLCipher database passphrase, so
  the app rejected the existing version-1 wrap, could not open the database and
  showed “The encrypted vault database could not be opened.”
- No data was lost: the wrapped passphrase and the vault were intact, only the
  version check rejected them.

## Fixes

- The shared wrapped-secret version is back to 1, so existing database
  passphrases unwrap and the vault opens again.
- Biometric migration is now tracked by a dedicated marker in the biometric
  store instead of the shared format version. A legacy biometric wrap is ignored
  safely, and the unlock screen explains that biometric unlock must be re-enabled
  once.
- After installing 2.2.8: unlock with the master password, then open
  Settings → Advanced settings → Enable biometric unlock. It then works across
  auto-lock and screen lock.
- All other 2.2.7 changes (time-bound biometric key, authenticate-then-decrypt
  flow, invalidated-key handling, CI toolchain pin) are retained.
