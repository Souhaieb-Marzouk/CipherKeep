# CipherKeep 2.3.6

CipherKeep 2.3.6 makes autofill generic across applications and adds an unlock
sheet that returns the user straight back to the login they were filling.

## Generic matching

Nothing is hard-coded to a specific application any more:

- Web pages are matched by registrable domain, so any subdomain matches its
  saved site (`sso.example.com` → `example.com`).
- Native apps are matched from their package name and application label tokens,
  so any app whose name appears in the login title, URL, username or notes gets
  suggestions.
- Browsers are detected generically by asking the package manager which
  installed packages handle `https://` links, instead of a fixed list. When a
  browser hides the origin, recent saved logins are offered.

## Unlock without leaving the login

- Tapping “Unlock CipherKeep” in the autofill popup now opens a small
  translucent sheet, not the CipherKeep main window.
- After a successful password or biometric unlock, the sheet builds the datasets
  and returns them through the Android autofill authentication result. Android
  fills the fields and the sheet closes, so the user lands back on the login page
  automatically.
- The main window opens only when the user launches CipherKeep themselves.
- The autofill service and the main UI share one process-wide session, so an
  unlock from autofill also unlocks the vault the user sees when they later open
  the app.

Verified on the OPPO CPH2173: with the vault locked, Crunchyroll showed the
“Unlock CipherKeep” card; tapping it opened the sheet over the login page;
biometric unlock filled the email and password and returned to Crunchyroll
without opening CipherKeep. A second request while unlocked still produced two
matching datasets.

## Compatibility

- Android only; no vault, record or relay protocol change. The signed Firefox
  2.2.4 package remains interoperable.
