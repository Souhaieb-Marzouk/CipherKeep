# CipherKeep 2.3.10

CipherKeep 2.3.10 repairs the Android CI job and hardens two API-level edge
cases found by the build.

## CI

- The unit test `AutofillMatchingTest` still asserted the old exact-host rule.
  It now verifies the shipped registrable-domain rule: subdomains of the same
  site match (`sso.crunchyroll.com` / `crunchyroll.com`, `chat.z.ai` / `z.ai`,
  `www` equivalence, explicit ports), while different sites, look-alike domains,
  public-suffix-only hosts (`co.uk`), empty origins and invalid URLs do not.
- `AssistStructure.ViewNode.maxTextLength` is API 28+, but the app supports
  API 26. The value is now read through a guarded helper (`-1` below API 28), so
  the split one-time-code detection compiles cleanly for API 26–27 and lint no
  longer reports `NewApi`.
- `AndroidSyncFolder.write` now returns `false` when the SAF rename fails instead
  of returning `true` while leaving a `.tmp` file behind (removes the
  “condition is always true” warning and reports a real failure).

## Verification

The full CI command passes locally on the same toolchain:

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest --no-daemon
```

20 unit tests, lint and the AndroidTest assembly all complete successfully.

## Compatibility

- Android only; no vault, record or relay protocol change. The signed Firefox
  2.2.4 package remains interoperable.
