# Security Policy

CipherKeep is a password manager, so security reports are treated as the highest-priority work.

**Status:** pre-release. No version is supported for production use, and there is no public release.

---

## Reporting a vulnerability

**Do not open a public issue, discussion, or pull request for a security problem.**

Use GitHub's private vulnerability reporting:

<https://github.com/Souhaieb-Marzouk/CipherKeep/security/advisories/new>

If that form is unavailable, open a minimal public issue asking the maintainer to enable a private channel **without describing the vulnerability**, and wait for a response.

Please include, as applicable:

- Affected artifact and version or commit.
- Platform and OS version.
- The impact: what an attacker gains and under what preconditions.
- Reproduction steps or a proof-of-concept. Use test data; never include real secrets.
- Whether the issue is already public, and any disclosure deadline.
- A suggested fix, if you have one.

### What to expect

| Stage | Target |
|---|---|
| Acknowledgement | 3 business days |
| Initial triage and severity | 7 business days |
| Fix or mitigation plan | 30 days for High/Critical |
| Coordinated disclosure | By agreement, default 90 days after triage |

We will credit reporters who want credit. We will not threaten legal action for good-faith research that respects privacy, avoids data destruction, and does not target other users. This is a statement of intent, not a legal safe-harbor policy. The project has no bug bounty and cannot pay rewards.

---

## Reporting a non-security bug

Use GitHub Issues with a minimal reproduction and no real credentials.
